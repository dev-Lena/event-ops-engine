# 용어 기준 — 용어집 만드는 법

같은 개념을 사람 · 문서 · 코드가 **다른 이름으로 부르지 않게** 한다. 이름이 갈리면 기획 · 디자인 · 코드 사이에서 같은 것을 다른 것으로 오해하고, 검색으로 찾지 못한다.
여기에는 **용어를 정하는 기준**만 둔다. 각 서비스의 실제 용어는 프로젝트 문서(예: `CONTRIBUTING.md` "용어" 절 또는 `docs/glossary.md`)에 적는다.

## 1. 기준

- **한 개념 = 한 이름.** 동의어를 섞어 쓰지 않는다. 비슷한 개념이 둘이면 이름도 분명히 다르게 짓는다.
- **사용자에게 보이는 문구와 코드 · API · 문서 용어를 따로 정할 수 있다.** 문구는 사용자가 알아듣는 말로, 코드는 정확하고 안정적인 말로. 대신 둘의 **대응표**를 반드시 둔다.
- **쓰지 않는 말(금지어)과 대신 쓸 말**을 적는다. 기획 초기에 쓰던 이름, 오해를 부르는 일반 용어 등.
- 언어별 표기를 함께 정한다 (한국어 문구 · 영어 문구 · 코드 식별자).
- **도메인 경계 규칙**(하루의 기준 시각, 통화 · 단위, 반올림 등)은 용어와 함께 적고, 계산은 **한 모듈만** 쓰게 한다. 여러 곳에서 따로 계산하면 경계에서 어긋난다 ([code-standards.md](code-standards.md) 2-1번과 같은 이유).
- 용어를 바꾸면 문구 · 코드 · 문서를 **같은 PR에서** 함께 바꾼다. 일부만 바꾸면 두 이름이 섞여 남는다.

## 2. 프로젝트 용어집 양식

```markdown
## 용어

| 개념 | 사용자 문구 (한국어 / 영어) | 코드 · API · 문서 | 쓰지 않는 말 | 메모 |
|---|---|---|---|---|
| <개념 설명> | <문구> / <문구> | `<identifier>` | <금지어> | <왜 이 이름인지> |

### 도메인 경계 규칙
- <규칙> — 계산은 `<모듈 경로>`만 쓴다.
```

## 3. 예 (LuckPlay)

| 개념 | 사용자 문구 (한국어 / 영어) | 코드 · API · 문서 | 쓰지 않는 말 |
|---|---|---|---|
| 매일 키링을 틀어 그날의 운을 여는 동작 | 틀다 / Turn on · Play | `tag` | — |
| 가입 때 사주로 한 번 받는 변하지 않는 나 | 본아 / Root Self | `rootSelf` | 페르소나 |

- 도메인 경계 규칙: 하루의 기준은 자정이 아니라 **사용자 시간대 23:30**이다. 날짜 계산은 `src/lib/saju/saju-day.ts`만 쓴다.
