# 보안 기준 — 비밀값 · 개인정보

어느 프로젝트든 **기본으로** 지키는 보안 규칙이다. 프로젝트 이름 · 기술에 기대지 않게 쓴다.
계정 분리(CLI 전역 로그인 금지, 토큰 파일)는 [environment-setup.md](environment-setup.md)에 있다.

| # | 규칙 | 한 줄 |
|---|---|---|
| 1 | [비밀값을 코드에 넣지 않는다](#1-비밀값을-코드에-넣지-않는다) | 환경변수로만, `.env.example`에는 이름만 |
| 2 | [비밀값 파일은 커밋하지 않는다](#2-비밀값-파일은-커밋하지-않는다) | `.env*` 등은 `.gitignore` |
| 3 | [배포 결과물에 비밀값이 없게](#3-배포-결과물에-비밀값이-없게) | 공개 변수 구분, 배포 전 자동 검사 |
| 4 | [개인정보를 외부 도구에 보내지 않는다](#4-개인정보를-외부-도구에-보내지-않는다) | LLM · 로그 · 분석 · 세션 녹화 |
| 5 | [비밀값이 새었을 때](#5-비밀값이-새었을-때) | 폐기 → 재발급 → 교체 |

## 1. 비밀값을 코드에 넣지 않는다

- API 키 · 토큰 · DB 비밀번호 · 서명 키는 **전부 환경변수**로 관리한다. 코드 · 설정 파일 · 테스트 · 주석에 실제 값을 쓰지 않는다.
- 필요한 키 **이름**은 `.env.example`에 적는다 (값은 비움, 어디서 발급하는지 주석). 새 사람이 `cp .env.example .env.local`로 시작할 수 있게.
- 용도가 다른 비밀값은 파일을 나눈다.

| 파일 (예) | 누가 읽나 | 넣는 값 |
|---|---|---|
| `.env.local` | 앱 (개발 서버 · 빌드) | 앱이 쓰는 키 |
| `.env.cli` | 배포 · 관리 CLI를 감싼 스크립트 | 관리 권한 토큰 (배포 · DB 관리) |
| 배포 플랫폼의 secret 저장소 | 배포된 서버 | 운영 비밀값 |

- 관리 권한 토큰을 앱 키 파일(`.env.local`)에 넣지 않는다 → 앱 프로세스에 배포 · 관리 권한이 들어간다.
- 운영 서버 비밀값은 **플랫폼 secret 저장소**에만 넣는다 (예: Cloudflare `wrangler secret put`). 저장소에 커밋되는 설정 파일의 일반 변수(`vars` 등)에 넣지 않는다.
- **AI가 자동으로 읽는 파일**(예: `CLAUDE.md`, `CLAUDE.local.md`)에 비밀번호 · 키 값을 쓰지 않는다. 세션마다 대화에 들어가 AI로 전송된다. 계정 이름 · 용도 · 키 **이름**까지만 적는다.

## 2. 비밀값 파일은 커밋하지 않는다

- `.env*`(단 `.env.example`은 커밋), 로컬 서버용 비밀값 파일(예: `.dev.vars`), CLI 토큰 파일은 `.gitignore`에 등록한다. 프로젝트를 만들 때 먼저 등록한다.
- 커밋 전에 `git status` · `git diff --staged`로 비밀값 파일이 올라가지 않았는지 본다.

## 3. 배포 결과물에 비밀값이 없게

- **브라우저로 가는 것은 전부 공개된다.** 정적 파일 · 번들 · 공개 환경변수는 누구나 열어 볼 수 있다고 보고 만든다.
- 브라우저에서 꼭 써야 하는 값만 **공개 접두사**를 붙인다 (예: Next.js `NEXT_PUBLIC_`, Vite `VITE_`). 이름에 붙이는 순간 공개된다.
- 오류 응답에 접속 주소 · 스택 · 내부 오류 메시지를 싣지 않는다. 사용자에게는 오류 키만, 자세한 내용은 서버 로그에만.
- **배포할 때마다 결과물을 자동 검사**하고, 하나라도 걸리면 배포를 멈춘다.

| # | 검사 |
|---|---|
| 1 | 로컬 비밀값 파일의 **실제 값 문자열**이 배포 결과물 어디에도 없다 |
| 2 | 공개 변수 값이 비밀값처럼 생기지 않았다 (예: `sk-`, `sb_secret_`, `postgres://`, `service_role`) |
| 3 | 공개 파일에 `.env*` · 소스맵(`.map`) · 인증서(`.pem` · `.key`)가 없다 |
| 4 | 빌드가 중간에 실패해 결과물이 온전하지 않으면 검사를 통과시키지 않는다 |

> 예 (LuckPlay): `npm run deploy` → `scripts/cf-build.sh` → `scripts/check-bundle-secrets.mjs`가 위 검사를 돌린다. 결과물만 따로 볼 때는 `npm run cf:check`.

## 4. 개인정보를 외부 도구에 보내지 않는다

- LLM 프롬프트 · 로그 · 분석 도구 · 오류 추적에 **이메일 · 비밀번호 · 인증 토큰**을 보내지 않는다.
- 서비스에 꼭 필요한 민감 정보(예: 생년월일시, 건강 · 위치 정보)는 **그 기능에 필요한 곳에만** 쓴다. 로그 · 분석 이벤트에 싣지 않는다.
- 세션 녹화 · 화면 캡처 도구(예: PostHog · Sentry Replay)에서는 입력칸과 민감 정보 영역을 **가린다**(mask).
- LLM에 보내야 하는 입력은 필요한 필드만 골라 보낸다 (사용자 레코드를 통째로 보내지 않는다).

## 5. 비밀값이 새었을 때

커밋 · 로그 · 채팅 · 스크린샷에 비밀값이 한 번이라도 노출되면 **지우는 것으로 끝내지 않는다** (기록 · 캐시에 남는다).

1. 발급한 곳에서 **즉시 폐기**(revoke · roll)한다.
2. 새로 발급해 로컬 파일 · 플랫폼 secret을 바꾼다.
3. 노출 기간 동안 그 키로 이상한 사용이 있었는지 대시보드에서 확인한다.
4. 무엇이 · 언제 · 어디에 노출됐고 어떻게 처리했는지 기록한다.
