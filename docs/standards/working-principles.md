# 작업 원칙

사람이든 Claude든 **모든 작업에 적용하는** 원칙이다. 프로젝트 이름 · 기술에 기대지 않는다.
바꾸기 전까지 유지하고, 바꾸면 이 폴더의 원본을 먼저 고친다.

| # | 원칙 | 한 줄 |
|---|---|---|
| 1 | [이유와 함께 제안한다](#1-모든-의사결정과-진행-과정은-이유와-함께-제안한다) | 무엇을 · 왜 · 검토한 대안을 먼저 보여주고, 결정할 것은 확인받고 진행 |
| 2 | [정확한 동작을 보장한다](#2-정확한-동작을-보장한다) | 완료라고 말하기 전에 실제로 실행 · 테스트 |
| 3 | [하이 퀄리티를 보장한다](#3-수준-높은-하이-퀄리티를-보장한다) | "동작한다"에서 멈추지 않고 시안 · 기획서 · 기준 수준까지 |
| 4 | [토큰을 효율적으로 쓴다](#4-토큰을-효율적으로-쓴다) | 낭비 · 누수 없이, 단 1~3을 해치면서까지 줄이지 않음 |

4는 1~3보다 뒤에 온다 — 토큰을 아끼려고 제안 · 확인 · 테스트 · 품질을 줄이지 않는다.

---

## 1. 모든 의사결정과 진행 과정은 이유와 함께 제안한다

- 무엇을 할지뿐 아니라 **왜 그렇게 하는지**(기준 · 검토한 대안)를 먼저 보여준다.
- **결정이 필요한 것은 확인받은 뒤** 진행한다. 되돌리기 어려운 것(배포 · 데이터 변경 · 외부 서비스 설정 · 공개 게시)은 특히 그렇다.
- 이미 정해진 것(이 기준 문서, 프로젝트 문서의 결정)은 다시 묻지 않고 따른다.
- 결정한 것은 기록이 남는 곳에 적는다 (PR 배경과 판단 근거 코멘트 — [git-workflow.md](git-workflow.md) 3번, 프로젝트 결정 문서).

## 2. 정확한 동작을 보장한다

- **완료라고 말하기 전에 실제로 실행 · 테스트해서 확인한다.** "고쳤을 것이다"는 완료가 아니다.
- **확인하지 못한 것은 확인하지 못했다고 적는다** (예: "로컬에서만 확인, 배포 환경은 미확인").
- 테스트가 실패하면 실패했다고 그대로 보고한다. 결과를 좋게 요약하지 않는다.
- 확인 방법은 [testing-standards.md](testing-standards.md)의 "PR 올리기 전"을 따른다.

## 3. 수준 높은 하이 퀄리티를 보장한다

- "동작한다"에서 멈추지 않고 **디자인 시안 · 기획서 · 공용 기준 문서**의 수준까지 맞춘다.
- 기능 요구사항에 없어도 공용 기준(품질 · 코드 · 보안 · 테스트)은 기본으로 갖춘다.
- 시안 · 기획과 다르게 만든 부분은 숨기지 않고 이유와 함께 PR에 적는다.

## 4. 토큰을 효율적으로 쓴다

**비효율적인 토큰 낭비와 누수가 없어야 한다. 단, 1~3을 해치면서까지 줄이지 않는다.**

- 필요한 파일 · 필요한 부분만 읽는다.
- 긴 출력은 걸러서 본다 (`grep` · `head` · 필터 옵션).
- 이미 확인한 것을 다시 확인하지 않고, 같은 작업을 되풀이하지 않는다.
- 도구 · 스킬 · MCP는 꼭 필요한 것만 켠다.
- **결과를 뒤엎는 재작업이 가장 큰 낭비다.** 결정이 필요한 것은 먼저 확인한다 (원칙 1).
