# 작업 시작 전 — 개발 환경 · 계정 확인

새 작업 세션(사람이든 Claude든)을 시작할 때 **작업 전에** 확인하는 순서와, 그 확인이 가능하도록 프로젝트를 준비하는 기준이다.
프로젝트 이름 · 기술에 기대지 않게 쓴다. 프로젝트가 쓰는 플랫폼 표 · 명령은 프로젝트 문서(예: `docs/session-setup.md`)에 적는다.

목적은 두 가지다.

1. 지금 이 컴퓨터 · 폴더에 **어떤 계정이 연결되어 있는지** 파악한다.
2. 이번 작업에서 **쓸 계정을 분명히 정한 뒤** 시작한다.

한 컴퓨터에서 여러 프로젝트를 하면 CLI · 브라우저 로그인이 다른 프로젝트 계정으로 남아 있기 쉽다. 확인 없이 시작하면 **다른 계정에 배포하거나 다른 DB를 바꾸는** 사고가 난다.

## 1. 원칙

- **계정의 기준은 Chrome 프로필이다.** 프로젝트는 어느 Chrome 프로필(= 계정 묶음)에 속하는지로 정한다. 그 프로필로 로그인한 계정으로만 대시보드 · 토큰 · 키를 만든다.
- **CLI는 전역 로그인을 쓰지 않는다.** 프로젝트 폴더의 토큰 파일만 쓴다 ([3번](#3-프로젝트-준비--계정-분리)).
- **이 컴퓨터의 계정 매핑은 저장소 루트의 `CLAUDE.local.md`에 적는다.** 개인 파일이라 커밋하지 않고, Claude Code가 세션마다 자동으로 읽는다 ([부록](#부록-claudelocalmd-양식)).
- **확인이 끝나기 전에는 외부 서비스에서 아무것도 만들거나 바꾸지 않는다.**

## 2. 세션 시작 체크리스트

### 1단계 — 현재 상태 파악 (스크립트)

프로젝트에 **환경 확인 스크립트**를 하나 두고(예: `npm run env:check`) 세션마다 실행한다. 비밀값은 출력하지 않고 "설정됨 / 비어 있음"과 계정 이름만 보여준다.

| 항목 | 보는 것 |
|---|---|
| 런타임 | 실행 중인 버전과 고정 버전 파일(예: `.nvmrc`) 일치 여부 |
| GitHub / git | 원격 저장소, 커밋 작성자(저장소 로컬 · 전역), 자격 증명 사용자 |
| 전역 로그인 | 프로젝트가 쓰는(또는 쓰지 않는) CLI가 전역으로 로그인 · 설치되어 있는지 — 있으면 **쓰지 않는다** |
| 토큰 · 키 파일 | CLI 토큰 파일 · 앱 키 파일이 채워졌는지 |
| 플랫폼 계정 | 토큰이 가리키는 계정 이름 · ID, 보이는 프로젝트 목록 |
| Claude 도구 | 프로젝트 스킬 · MCP · 플러그인이 기대한 대로 있는지 |

### 2단계 — 이번 작업에서 쓸 계정 정하기

`CLAUDE.local.md`의 계정 표와 1단계 결과를 비교한다. 프로젝트 문서에는 아래 모양의 표를 둔다.

| 영역 | 이 프로젝트에서 쓰는 것 | 계정을 정하는 곳 | 확인 방법 |
|---|---|---|---|
| 코드 저장소 | GitHub `<owner>/<repo>` | 저장소 로컬 `git config` | 환경 확인 스크립트 |
| CLI | 배포 · DB CLI | CLI 토큰 파일 + 감싼 실행 명령 | 환경 확인 스크립트 |
| DB · 인증 | … | 앱 키 파일 | 마이그레이션이 성공하는지 |
| 서버 · 호스팅 | … | CLI 토큰 파일 + 배포 설정의 계정 ID | `whoami` 류 명령 |
| LLM · 분석 · 관측 · 알림 | … | 앱 키 파일 | 대시보드 |
| 디자인 · 브라우저 | Figma, Chrome 프로필 | 브라우저 · MCP 로그인 | 3단계 |
| 쓰지 않음 | … | — | 쓰게 되면 이 표와 토큰 파일에 추가 |

**맞지 않으면 여기서 멈추고 고친다.** 예: 토큰이 다른 계정을 가리킴 → 올바른 프로필에서 토큰 재발급, 저장소 로컬 git 작성자가 없음 → [3번](#github-git)의 git 설정.

### 3단계 — 브라우저 확인 (직접)

스크립트로는 확인할 수 없어서 직접 본다.

| 브라우저 | 확인할 것 |
|---|---|
| Chrome (사람) | 이 프로젝트가 속한 **Chrome 프로필 창**에서 작업하고 있는지 |
| Claude in Chrome | 연결된 브라우저가 여러 개면 이 프로젝트의 프로필을 고른다 (연결할 때 브라우저 이름을 프로필 이름으로 지어두면 헷갈리지 않는다) |
| Claude 앱 내장 브라우저 | 모든 세션이 프로필 하나를 같이 쓴다 → **계정 작업에는 쓰지 않는다** |
| 로그인 없는 자동화 브라우저 (예: agent-browser, Playwright) | 화면 확인 · 스크린샷 전용 → **계정 작업에는 쓰지 않는다** |

어느 브라우저든 사이트에서 무언가 만들거나 바꾸기 전에 **그 사이트에 로그인된 이메일을 먼저 확인한다.** 예상과 다르면 즉시 멈춘다.

### 4단계 — 확인 결과 공유 후 시작

Claude 세션은 1~3단계 결과를 한 표(영역 · 지금 연결된 계정 · 이번에 쓸 계정 · 일치 여부)로 사용자에게 보여주고, 불일치나 빈 값이 있으면 무엇을 할지 먼저 묻는다. 모두 일치하면 그대로 작업을 시작한다.

## 3. 프로젝트 준비 — 계정 분리

### CLI는 프로젝트 토큰으로만

- CLI 관리 토큰은 프로젝트 루트의 **CLI 토큰 파일**(예: `.env.cli`, 커밋 안 함)에 둔다. `.env.cli.example`에 이름만 적어 둔다.
- CLI는 **감싼 실행 명령**으로만 부른다 (예: `npm run cf -- <명령>`). 감싼 스크립트가 토큰 파일을 읽어 **그 명령 하나에만** 토큰을 넣는다. 셸 전체에 `export`하지 않으므로 다른 터미널 · 프로젝트에 영향이 없다.
- 토큰 파일이 없거나 값이 비어 있으면 **실행을 멈춘다.** 전역 로그인으로 조용히 넘어가지 않게 하기 위해서다.
- 많은 CLI는 토큰 환경변수가 전역 로그인보다 우선한다 (예: wrangler의 `CLOUDFLARE_API_TOKEN`, Supabase CLI의 `SUPABASE_ACCESS_TOKEN`). 새 CLI를 붙일 때 이 우선순위를 확인한다.
- 전역 로그인 명령(예: `wrangler login`, `supabase login`, CLI 직접 실행)은 프로젝트 폴더에서 쓰지 않는다. Claude Code 세션에서는 프로젝트 `.claude/settings.json`의 `permissions.deny`로 막는다.
- 토큰은 **그 프로젝트 계정 · 리소스만** 고른 최소 권한으로 만든다. 만든 뒤 `whoami` 류 명령으로 계정이 맞는지 확인한다.

> 예 (LuckPlay): `scripts/with-cli-account.sh`가 `.env.cli`를 읽어 `npm run cf`(wrangler) · `npm run sb`(Supabase CLI)에만 토큰을 넣는다.

### GitHub (git)

전역 `~/.gitconfig`가 바뀌어도 이 프로젝트의 커밋 작성자 · 푸시 계정이 바뀌지 않도록 **저장소 로컬 설정에 고정**한다.

```bash
git config --local user.name "<이름>"
git config --local user.email "<GitHub noreply 이메일>"
git config --local credential.https://github.com.username "<키체인에 저장된 사용자명>"
```

`credential.…username`을 지정하면 키체인에 GitHub 계정이 여러 개 있어도 그 사용자의 자격 증명만 쓴다.

비밀값 파일을 나누는 법 · 커밋 금지 · 새었을 때 처리는 [security-standards.md](security-standards.md)를 따른다.

## 4. 이름 · 주소 규칙

서비스에서 만드는 **이름과 주소에는 기본적으로 개인 계정 이름(이메일 아이디 · 사람 이름)을 넣지 않는다.** 프로젝트 이름으로 짓는다. 개인 이름은 외부에 그대로 노출되고, 나중에 계정을 옮기거나 사람이 바뀌면 주소를 바꿔야 한다.

| 대상 | 규칙 | 예 |
|---|---|---|
| 배포 주소 (`*.workers.dev` · `*.pages.dev` · `*.vercel.app` 등) | 계정 하위 도메인 = 프로젝트 이름, 앱 이름 = 역할 | `app.<project>.workers.dev` |
| 클라우드 프로젝트 · DB | `<프로젝트>-<환경>` | `<project>-dev` · `<project>-prod` |
| API 키 · 토큰 이름 | `<프로젝트>-<용도>` | `<project>-cli`, `<project>-dev` |
| 조직 · 계정 표시 이름 | 플랫폼이 자동으로 개인 이름을 붙이면(예: "○○'s Account") 바꿀 수 있을 때 프로젝트 이름으로 바꾼다 | — |

- 예외는 **요구사항이 있을 때만** 둔다 (예: 개인 포트폴리오 주소). 예외를 두면 이유를 PR에 적는다.
- 한 계정의 여러 프로젝트가 계정 하위 도메인을 같이 쓰는 경우(workers.dev는 계정당 하나)에는 하위 도메인을 대표 프로젝트 이름으로 두고 앱 이름으로 구분한다.
- 운영 주소는 개인 이름이 없는 자체 도메인을 연결한다.

## 5. 새 플랫폼을 추가할 때

1. 그 플랫폼 계정을 이 프로젝트의 Chrome 프로필로 만든다. 프로젝트 · 주소 이름은 [4번](#4-이름--주소-규칙)을 따른다.
2. CLI 토큰이면 `.env.cli.example` · `.env.cli`에, 앱 키면 `.env.example` · `.env.local`에 넣는다.
3. CLI라면 감싼 실행 스크립트에 필수 변수 검사를 추가하고, `.claude/settings.json`에 전역 명령 차단(`deny`)을 추가한다.
4. 프로젝트 문서의 2단계 표와 환경 확인 스크립트에 한 줄씩 추가한다.
5. `CLAUDE.local.md`의 계정 표에 계정을 적는다.

## 부록. `CLAUDE.local.md` 양식

저장소 루트에 만든다 (`.gitignore`에 등록, 커밋 안 함).

> **비밀번호 · 앱 비밀번호 · API 키는 이 파일에 절대 쓰지 않는다.** Claude Code가 세션마다 자동으로 읽어 대화에 포함하므로 적은 값이 AI에 전송된다 ([security-standards.md](security-standards.md) 1번). 계정 이름 · 용도 · 설정 위치 · 키 **이름**까지만 적고, 값은 비밀번호 관리자나 토큰 · 키 파일(스크립트만 읽음)에 둔다.

```markdown
# 이 컴퓨터의 계정 매핑 (개인 설정, 커밋 안 함)

## Chrome 프로필
| 프로필 | 로그인 계정 | 이 프로필로 하는 프로젝트 |
|---|---|---|
| <프로필 이름> | <이메일> | <이 프로젝트>, … |
| <다른 프로필> | <이메일> | <다른 프로젝트> — 이 프로젝트에서는 쓰지 않음 |

## <프로젝트> 계정
| 플랫폼 | 계정 · 조직 · 프로젝트 | ID |
|---|---|---|
| GitHub | … | |
| <호스팅> | … | 계정 ID |
| <DB · 인증> | 조직 / 프로젝트 | project ref |
| <LLM> | 조직 / 프로젝트 | 프로젝트 ID |
| 메일 발송 (SMTP) | 발송 계정 · 서버 · 설정 위치 | 앱 비밀번호 **이름** (값은 쓰지 않음) |
```
